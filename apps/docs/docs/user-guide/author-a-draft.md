# Author a draft

This page shows you how to write a new policy or procedure and send it for approval.

A draft is the first version of a document. It is a work in progress that only you and a few
others can see. Here is how to write one and pass it along to be reviewed.

## ✍️ Who can author

Authoring is controlled **per category**, not by a single global role. You can create and edit
drafts in a category if either of these is true:

- You are an **owner** of that category (or of a parent category above it), or
- The category's access rules grant you the **Author** action, directly or through a directory
  group you belong to.

If you cannot find a "new draft" option in a category, you most likely do not have Author access
there. Ask your administrator — see [Who can do what](/concepts/access-model).

## 📝 The steps

1. **Start a draft.** Choose **New policy** or **New procedure** in the library's header, or from
   the search panel (Shift+C). Pick the type, give it a clear, specific title, and choose its
   **Category** and, if it has them, a **Subcategory**.
2. **Pick a template and sensitivity.** The category decides the **approval workflow** the draft
   follows, and later **who must acknowledge** the published document. Choose a **Template** (or
   **No template (freeform)**) and whether it's **Standard** or **Sensitive**, then **Create
   policy**.
3. **Use the template's sections.** If you chose a template, your draft starts with its headings
   already in place. The **Required sections** list beside the editor ticks each required section
   once it has content.
4. **Write the content**, using headings, lists, tables and links to keep it organised. Add
   supporting material under **Appendices**, beside the editor.
5. **Save draft** keeps your work; the header says **Saved** or **Unsaved changes**.
6. **Submit for approval.** Steward asks you to confirm before the draft goes to its approvers. If
   a required section is still empty, it tells you which instead. You can't edit the draft while
   it's in review.

To throw a draft away, choose **Actions → Discard draft…**. A published version stays live.

:::note
While you write with others, Steward keeps the shared draft as you go. On your own, use **Save
draft** before you leave; an unfinished **New policy** form is kept in your browser so you can
come back to it.
:::

## 👥 Writing together

More than one author can open the same draft at once. The header shows who else is in it and
**Editing together** (or **Reconnecting…** if the connection drops). You see each other's cursor
and changes as they happen, so you never overwrite one another's work.

## 🤖 AI assistance

Where an organisation has turned it on at install, Steward can draft or suggest text for an empty
section, or offer to improve a section you have already written. AI assistance is an optional
feature your organisation's administrator chooses when Steward is set up; it has no effect on
drafts if it was not switched on for your installation.

## 👀 After you submit

Once submitted, your draft moves into review and is out of your hands until the approvers act:

- If it is **approved** through every stage, it is **published** so others can read it.
- If an approver **requests changes**, the draft comes back to you to revise and resubmit.

See the [document lifecycle](/concepts/lifecycle) page for the whole path, and the approver's side
in [Review and approve](/user-guide/review-and-approve).

## 🔄 Updating a published document

To change a document that is already published, start a **new draft** of it. The published version
stays in force for readers while you work; your new draft goes through the same review and
approval path, and only replaces the live version once it is approved and published.
